# 13.2 The distribution model

One 2D device mesh with axes `('x', 'y')` spans all processes for the whole run.
The governing convention completes the picture of §4.1 and Chapter 5:
**two-point objects are sharded over their two spatial-basis axes on the processor
grid.** $G$, $\chi$, $W$, $V_q$, and Σ in the ISDF basis live as
$K(\ldots, \mu_X, \nu_Y)$ with the centroid axes tiled over mesh rows and columns;
ζ and grid-resolved intermediates shard one centroid axis against the flattened
grid axis. K- and q-axes are kept replicated or flattened into batch dimensions
("flat-k"), never used as sharding axes, so lattice FFTs (§4.3) run locally per
device.

Consequences. Dense contractions become local GEMM tiles plus mesh-row/column
collectives, which XLA inserts from the sharding declarations; the 2D-blocked
factorizations (§5.3) and the FFI backends (§12.3) operate on the same tile
layout, so no resharding separates fit, screening, and Σ. Per-device memory falls
as the pool grows because every large axis is tiled. Two idioms recur in the
source: `shard_map` with explicit `PartitionSpec`s for kernels where the
compiler's default partitioning would replicate (the fit kernel, the per-τ Σ
kernel), and two-stage reshards through an intermediate spec where a direct
transition would materialize a replicated copy.
