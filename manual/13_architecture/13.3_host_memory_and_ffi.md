# 13.3 Host memory discipline; the FFI layer

Large read-only data lives in host RAM, not device memory. The G-space
wavefunction store (`common/psi_G_store.py`) holds ψ(G) for all bands on the host
and serves per-chunk slices into compiled code through `io_callback`, so device
memory holds only the working set of the current chunk; the same pattern serves
the disk-resident ζ store during $V_q$. The complementary rule: no replicated
device intermediates. Any buffer that would exist identically on every device is
treated as a defect and eliminated by sharding or streaming, and the memory
planner's peak model (§12.2) assumes this invariant.

The FFI layer wraps each native library behind XLA custom calls with per-platform
(CUDA/CPU) registration, capability probing at import, and a common
tile-layout validation shared by all backends. Handlers receive the local shards
of mesh-tiled arrays plus the process-grid descriptor, so a backend swap
(`cusolvermp` ↔ `slate` ↔ pure JAX) changes no caller. Adding a backend means one
subdirectory under `src/ffi/` implementing the handler signature, a stage or
build script, and a row in the contract test; `src/ffi/PORTING.md` is the
checklist.
