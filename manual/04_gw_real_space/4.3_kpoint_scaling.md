# 4.3 k-points: $O(N_k \log N_k)$ runtime, $O(N_k)$ memory

Every two-point object carries a momentum transfer coupling $\mathbf{k}$ to
$\mathbf{k}-\mathbf{q}$, and every k-sum in the code has the convolution form
$\sum_\mathbf{k} A^*_{\mathbf{k}-\mathbf{q}} B_\mathbf{k}$: in $\chi^0_\mathbf{q}$,
in the ISDF fitting matrices (§5.3), in $W$ and Σ. Evaluated directly, each of
$N_k$ momentum transfers costs a sum over $N_k$ k-points, $O(N_k^2)$ overall, the
cost paid by plane-wave G-space codes.

The k-grid is a regular lattice, so the convolution theorem applies. With the
lattice Fourier transform $P_\mathbf{R} = N_k^{-1/2}\sum_\mathbf{k}
e^{i\mathbf{k}\cdot\mathbf{R}} P_\mathbf{k}$,

$$
\sum_\mathbf{k} A^*_{\mathbf{k}-\mathbf{q}} B_\mathbf{k}
= \sum_\mathbf{R} e^{i\mathbf{q}\cdot\mathbf{R}}\, A^*_\mathbf{R}\, B_\mathbf{R}:
$$

transform once ($O(N_k \log N_k)$ by FFT), multiply pointwise, transform back, and
all momentum transfers are obtained simultaneously. Every k-convolution in the code
runs through this identity, so full-Brillouin-zone runtime scales as
$O(N_k \log N_k)$, an advantage that grows with grid density.

The price: the convolution theorem requires the whole lattice in memory at once,
$P_\mathbf{R}(\mathbf{r}_\mu,\mathbf{r}_\nu)$ for all $N_k$ lattice vectors, so
device memory scales linearly in $N_k$ where a one-$\mathbf{q}$-at-a-time pipeline
has an $N_k$-independent working set. The minimum device pool is set by system size
and k-grid together (the planner, §12.2, does the arithmetic), and adding GPUs
lowers the per-device footprint since all lattice and centroid axes are sharded
(Ch. 13).

Where the little group allows, ζ, $V_q$, and $\Sigma_x$ are computed on the
irreducible wedge and unfolded (App. A).
