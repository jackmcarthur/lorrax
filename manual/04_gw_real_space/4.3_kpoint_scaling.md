# 4.3 k-points: $O(N_k \log N_k)$ runtime, $O(N_k)$ memory

Restore the k-labels suppressed in §4.2. In a periodic system every two-point object
carries a momentum transfer: the polarizability at wavevector $\mathbf{q}$ couples
wavefunctions at $\mathbf{k}$ and $\mathbf{k}-\mathbf{q}$,

$$
\chi^0_\mathbf{q}(\cdots) \;\sim\; \sum_{\mathbf{k}} \big[\psi^*_{\mathbf{k}-\mathbf{q}}\psi_{\mathbf{k}}\big]
\big[\psi^*_{\mathbf{k}-\mathbf{q}}\psi_{\mathbf{k}}\big]^{*},
$$

and the same $\sum_\mathbf{k}(\mathbf{k}-\mathbf{q},\mathbf{k})$ structure appears in
the ISDF fitting matrices (§5.3), in $W$, and in $\Sigma$. Evaluated literally, each of
the $N_k$ momentum transfers costs a fresh sum over $N_k$ k-points: $O(N_k^2)$ overall.
This is what conventional G-space codes pay.

LORRAX never evaluates these sums directly. A sum of the form
$\sum_\mathbf{k} A^*_{\mathbf{k}-\mathbf{q}} B_\mathbf{k}$ is a **convolution over the
k-grid**, and the k-grid is a regular lattice — so the convolution theorem applies.
Define the lattice Fourier transform to Born–von Kármán lattice vectors $\mathbf{R}$:

$$
P_\mathbf{R} = \frac{1}{\sqrt{N_k}}\sum_\mathbf{k} e^{i\mathbf{k}\cdot\mathbf{R}}\, P_\mathbf{k}
\qquad\Longrightarrow\qquad
\sum_\mathbf{k} A^*_{\mathbf{k}-\mathbf{q}} B_\mathbf{k}
= \sum_\mathbf{R} e^{i\mathbf{q}\cdot\mathbf{R}}\, A^*_\mathbf{R}\, B_\mathbf{R}.
$$

Transform once ($O(N_k \log N_k)$ by FFT), multiply pointwise in $\mathbf{R}$
($O(N_k)$), transform back. **All momentum transfers $\mathbf{q}$ are obtained
simultaneously** from one pass. Every k-convolution in the code — pair-density
fitting, polarizability assembly, self-energy accumulation — runs through this one
identity (as direct lattice FFTs in the fitting kernels and via the flat-k FFT
helpers elsewhere), and the full-Brillouin-zone runtime scales as
$O(N_k \log N_k)$. To our knowledge no other production GW code exploits this, and
it is the reason LORRAX's advantage *grows* with k-grid density.

**The price is paid in memory.** The convolution theorem requires holding objects on
the *whole lattice at once*: $P_\mathbf{R}(\mathbf{r}_\mu, \mathbf{r}_\nu)$ for all
$N_k$ lattice vectors $\mathbf{R}$, rather than one $\mathbf{q}$-slice at a time.
Device memory therefore scales **linearly in $N_k$**, where a
one-$\mathbf{q}$-at-a-time pipeline (BerkeleyGW) has an $N_k$-independent working set.
Two consequences the user must internalize:

- The minimum device pool for a calculation is set by system size *and* k-grid
  together (the memory planner, §12.2, does this arithmetic for you).
- Throwing more GPUs at a LORRAX run genuinely helps memory, because all lattice-
  and centroid-axes are sharded across the pool (Ch. 13); the per-device footprint
  falls as the pool grows.

This trade — memory, the poolable and cheap resource on GPU clusters, spent to buy a
runtime scaling no one else has — restates the design position of §1.3 in mechanistic
terms.

Symmetry softens both sides: wherever the little group allows it, LORRAX computes on
the irreducible wedge and unfolds (ζ, $V_q$, $\Sigma_x$ ride this "IBZ cascade"), with
the unfolding equations and the honest list of what is and is not symmetry-reduced in
Appendix A.
