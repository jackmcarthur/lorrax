# 8.4 Running a bispinor calculation; status

A bispinor run is the scalar input plus:

```ini
bispinor = true
centroids_file          = centroids_frac_640.txt          # charge set
centroids_file_current  = centroids_frac_209_current.txt  # transverse set
whead_imfreq = 0.0        # dynamic head override; required for GN-PPM today
```

with the second centroid file generated by
`python -m centroid.kmeans_cli <M> --density-mode current`. Both static COHSEX and
GN-PPM `compute_mode` values run; the bispinor GN-PPM regression gate is one of the
frozen test-suite pins (§13.5). Plan band counts about 3× below the scalar ceiling
for the same hardware (§8.2), or let the planner refuse for you.

Status. Validated today: one-shot DHF + bare-Breit exchange on top of
charge-channel screening (static and GN-PPM). Not yet built: transverse screening,
i.e. the Dyson inversion of the coupled Lorentz-block dielectric matrix that would
turn $D^{ij}$ into a screened $W^{ij}$; the design fork is charge-only screening
(the present state) versus the full Lorentz supermatrix, and the machinery of
§7.3 is the template for either. Self-consistent bispinor iterations drop
$\Sigma^B$ and are not supported. Expected magnitudes at production settings:
Breit corrections to individual quasiparticle levels are tens of meV in 4d/5d and
halide systems, sub-meV in light-element solids, consistent with the
$\alpha_{\rm FS}^2$ scaling of §8.1.
