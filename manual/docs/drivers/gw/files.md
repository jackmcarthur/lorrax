## Outputs {: #outputs }

`tmp/` is `<run>/tmp`. Every text file is written on the WFN's irreducible wedge, one block per WFN k point.

<div class="file-list" markdown>

`<run>/eqp0.dat`, `<run>/eqp1.dat`
:   BerkeleyGW-format QP energies (`eqp0_file`, `eqp1_file`). In a QSGW run both hold the converged spectrum ([Terminal files](../../theory/qsgw.md#out-files)).

`<run>/sigma_diag.dat`
:   The diagonal of Σ per $\bk$ and band, decomposed (`sigma_diag_file`).

`<run>/eqp_g0w0.dat`
:   Dynamic one-shot runs: the diagonal of $T+V^{\mathrm{ion}}+V^{\mathrm H}+\Sigma^{xc}(E_{n\bk})$.

`sigma_freq_debug.dat`
:   `sigma_freq_debug_output = true` only: the per-band decomposition table (`sigma_freq_debug_file`). Not written by a dynamic QSGW run on shell.

`<run>/sigma_mnk.h5`
:   `gn_ppm`, `hl_ppm` and `mpa` only: the Σ band matrices and the eqp assembly receipt (`sigma_omega_h5_file`).

`<run>/qp_wfn_rotations.h5`
:   $U_\bk$ and $E^{\mathrm{QP}}_{n\bk}$ with the source-WFN fingerprint.

`<run>/WFN_qp.h5`
:   The orbitals rotated by $U$, with $E^{\mathrm{QP}}$ (`write_wfn_h5 = true`, the default).

`tmp/isdf_tensors_<N_mu>.h5`
:   The restart bundle: $V_\bq$, $W_0$, the head scalars and the parent wavefunction faces (`write_restart_tensors = true`, the default).

`tmp/zeta_q.h5`
:   $\zeta_{\bq\mu}(\bG)$ with its fit provenance.

`tmp/mpa/`
:   Shared-pole models and exports, or the elementwise-MPA sample and fit stores.

`tmp/sigma_checkpoint_oneshot_on_shell.h5`, `tmp/sigma_checkpoint_oneshot.h5`
:   One-shot shared-pole runs whose Σ sweep took at least 5× its predicted write (`write_restart_tensors = true`): the swept on-shell pair and slots, or under `sigma_omega_grid_debug = true` the Σ(ω) cubes. Reused on `restart = true`.

`<run>/gwjax.out`
:   The run report (`report_file`).

## eqp0.dat and eqp1.dat format {: #eqp }

`eqp_bgw.write_bgw_eqp`
{: .in-code }

Plain text in BerkeleyGW's `sigma_main.f90` layout, after one provenance line:

```text
# Generated by LORRAX <version> at 2026-10-19 08:41:07 UTC
  0.000000000  0.000000000  0.000000000       8
       1       1   -5.812330000   -6.420118000
       1       2    6.204411000    5.719882000
     ...
```

| Field | Content |
|---|---|
| line 1 | `# Generated by LORRAX <version> at <UTC time>` |
| block header `(3f13.9, i8)` | $\bk$ in crystal coordinates, then the number of band rows |
| col 1 `i8` | spin index, always `1` |
| col 2 `i8` | absolute band index, 1-based |
| col 3 `f15.9` | $E_{n\bk}$, eV |
| col 4 `f15.9` | $E^{\mathrm{QP}}_{n\bk}$, eV |

Rows run over the Σ window, bands `1` to $b_3 = n_{\mathrm{elec}}+n_{\mathrm{cond}}$. The writer refuses a non-finite energy, and re-reads the file to confirm that it parses to finite numbers; `LORRAX_ALLOW_NONFINITE_RESULT=1` writes it anyway.

In a one-shot run `eqp0.dat` holds $E_{n\bk}+\Delta_{n\bk}$ and `eqp1.dat` holds $E_{n\bk}+Z_{n\bk}\Delta_{n\bk}$, with $\Delta_{n\bk}$ the diagonal of $T+V^{\mathrm{ion}}+V^{\mathrm H}+\Sigma^{xc}(E_{n\bk})$ minus $E_{n\bk}$. Static treatments have $Z=1$, so the two files are equal. With band extrapolation on, compare the `eqp0_raw` and `eqp1_raw` columns of `sigma_diag.dat` with BerkeleyGW.

$Z$ is not clipped: the log counts states with $Z$ outside $(0,1]$, and a non-finite $Z$ refuses (`GATE z_factor_finite`).

In a QSGW run both files hold the same spectrum, the eigenvalues of the accepted map, with two `#` comment lines saying so.

## sigma_diag.dat format {: #sigma-diag }

`sigma_output.write_sigma_to_file`
{: .in-code }

A header, then one block per $\bk$. All values are in eV.

```text
# Generated by LORRAX <version> at 2026-10-19 08:41:07 UTC
# Sigma output (all in eV)
# sigXC = sigX + sigC
# Z is 1/(1 - dRe sigC/dw) from the exact on-shell derivative at E_DFT
# sigC_raw, eqp0_raw, eqp1_raw: raw = band sum truncated at N bands, no spectral_shell tail; compare to BerkeleyGW at the same number_bands
# k-basis: irreducible wedge, 8 k-points; each block states its crystal coordinate on a '# kcrys' line

k-point 0:
# kcrys     0.000000000    0.000000000    0.000000000
----------------------------------------------------------------------------------------------------
n=0   sigX=  -17.412337              sigC=    5.102118+ -0.213440i  sigXC=  -12.310219+ -0.213440i  VH=  ...
```

| Item | Content |
|---|---|
| `# <total> = <x> + <corr>` | `sigXC = sigX + sigC` in `gn_ppm`, `hl_ppm` and `mpa`; `sigTOT = sigSX + sigCOH` in `cohsex` and `x_only` |
| optional header lines | the `sigCC`/`sigTT`/`sigCT` sum rule, the `sigC_odd` definition, the `Z` definition, the raw-column note, `star_spread_ev` diagnostics, a `# omitted:` line naming dropped columns |
| `k-point <i>:` | position in the wedge, 0-based |
| `# kcrys` `(3f15.9)` | $\bk$ in crystal coordinates |
| `n=<i>` | band position in the Σ window, 0-based |
| `sigX` / `sigSX` | bare exchange, or screened exchange |
| `sigC` / `sigCOH` | $\Sigma^c(E_{n\bk})$, or Coulomb hole |
| `sigXC` / `sigTOT` | their sum |
| `sigCC`, `sigTT`, `sigCT` | bispinor runs: the charge, transverse and mixed sectors of the total |
| `sigC_odd` | bispinor runs with broken time reversal: the odd part of $\Sigma^c$ |
| `VH` | $V^{\mathrm H}$; `Hdir` when a transverse direct field is added |
| `Eo` | $E_{n\bk}$ |
| `Z` | the eqp1 factor, unclipped; only when eqp1 is linearized at $E_{n\bk}$ |
| `sigC_raw`, `eqp0_raw`, `eqp1_raw` | one-shot runs with band extrapolation: the band sum truncated at `number_bands_sigma`, and the eqp pair built from it |

Fields are `{:>12.6f}`; `eqp0_raw` and `eqp1_raw` are `{:>15.9f}`. A column that is complex anywhere in the file carries `+{:>10.6f}i` on every row; a real column is padded with 12 spaces, so columns stay aligned. In a QSGW run `sigma_diag.dat` holds the final Σ on the mean-field states; a dynamic QSGW run on shell has no $\Sigma^c(E_{n\bk})$ there, so `sigC` and `sigXC` are left out and named on the `# omitted:` line (`sigma_omega_grid_debug = true` writes them).

## eqp_g0w0.dat format {: #eqp-g0w0 }

`sigma_output.write_eqp_g0w0`
{: .in-code }

Written by one-shot runs whenever $\Sigma^c(E_{n\bk})$ exists, that is in `gn_ppm`, `hl_ppm` and `mpa`. The block layout of `sigma_diag.dat`, with an 80-dash rule:

```text
# Generated by LORRAX <version> at 2026-10-19 08:41:07 UTC
# G0W0 diagonal energies (eV)
# columns: band  E_DFT  Re[H0+Sigma_xc(E_DFT)]  Im[H0+Sigma_xc(E_DFT)]

k-point 0:
# kcrys     0.000000000    0.000000000    0.000000000
--------------------------------------------------------------------------------
n=0    E_DFT=   -5.812330  Re=   -6.401233  Im=   -0.213440
```

`Re` and `Im` are the diagonal of $T+V^{\mathrm{ion}}+V^{\mathrm H}+\Sigma^{xc}(E_{n\bk})$, eV: a diagonal element, not an eigenvalue.

## sigma_freq_debug.dat format {: #freq-debug }

`gw_output.write_freq_debug`
{: .in-code }

A provenance line, a title line, a `#` header naming the columns, then the `k-point <i>:` / `# kcrys` blocks. Each row is tab-separated, `{:>+16.6f}` per value, starting with the `k` and `n` positions; a complex column splits into `<name>.Re` and `<name>.Im`. The columns are `E_dft`, `Edft-Ef`, `kin_ion`, `V_H`, `Hdir`, `x_bare`, the head decomposition, then `sig_c(Edft)`, with `E_eval` and `sig_c(Eeval)` where Σ was read away from $E_{n\bk}$, and `sig_c_head(Edft)` (dynamic), or `sex_0`, `coh_0` (static), and `eqp0`, `eqp1` from the same assembly as `eqp0.dat` and `eqp1.dat`. On shell the Σ columns are reads of the one-shot on-shell values, and a dynamic QSGW run skips the file with a message; under `sigma_omega_grid_debug = true` they are reads of the Σ(ω) grid.

## gwjax.out {: #report }

The rank-0 run report (`report_file`): environment, sampling, band windows and ζ-fit legs, the treatment, per-stage progress and timings, warnings, the QP gaps, and on QSGW runs one row per map. No driver reads it.

## Restart bundle {: #restart }

`tagged_arrays.write_restart_state_to_h5`
{: .in-code }

`tmp/isdf_tensors_<N_mu>.h5`, with $N_\mu$ the row count of `centroids_file`. Generated from `write_restart_state_to_h5` (a `w` pass and an `a` pass), the centroid stamps in `gw_init._write_fresh_restart`, and `gw_output.persist_w0_and_head`. Small root entries go through SlabIO's `write_attr`, which writes datasets, not HDF5 attributes; `@` marks a true HDF5 attribute. Bracketed entries are conditional.

```tree
tmp/isdf_tensors_<N_mu>.h5
  @centroids_charge_md5            str              content hash of centroids_file
  @charge_representation           str
  [@centroids_transverse_md5]      str              bispinor
  lorrax_io_committed              int32[1]         1 once the last writer has closed
  restart_format_version           int64            2
  qp_state_source_provenance       bytes            JSON: source-WFN fingerprint
  [charge_zeta_identity]           bytes[2]         scheme, digest of the charge ζ fit
  [bispinor_v_receipt]             bytes[1]         copy of v_q_bispinor.h5's receipt
  kgrid                            int64[3]
  band_window_schema               int64            2
  band_window                      int64[5]         b0 b1 b2 b3 b4
  band_window_carrier              int64[5]
  band_window_split                int64[2]         chi top, Sigma top
  zeta_fit_windows                 int64[4]         L0 L1 R0 R1
  n_rmu_logical                    int64            N_mu
  coulomb_policy                   bytes            v1;key=value;...
  V_qmunu                          complex128[N_q, N_mu, N_mu]      @V_ready
  [V_qmunu__qirr/]                 q-wedge unfold tables
  G0_mu_nu                         complex128[N_mu]                 zeta(q=0, G=0)
  enk_full                         float64[N_k, N_b]                Ry
  psi_parent_k_rows                int64[N_p]
  psi_parent_y                     complex[N_p, N_b, n_s, N_mu]     @psi_layout
  psi_parent_y_mun                 complex[N_p, n_s, N_mu, N_b]     @psi_layout
  [psi_parent_y_transverse]        complex[N_p, N_b, 4, N_T]
  [psi_parent_y_transverse_mun]    complex[N_p, 4, N_T, N_b]
  [n_rmu_transverse_logical]       int64            N_T
  W0_qmunu                         complex128[N_q, N_mu, N_mu]      @W0_ready [@screening_diagrams]
  [W0_qmunu__qirr/]                q-wedge unfold tables
  [vhead]                          complex128       Ry bohr^3
  [whead]                          complex128[n_w]                  @omega_grid [@head_correction @response_kind @head_source]
  [S_cart_head]                    complex128[3, 3]                 @convention @omega_ry
  [W0_lr/]                         Ft P gvec v q_frac               @n_z @sys_dim @head_kernel @convention
  [shared_pole_member]             bytes[4]         path, schema, digest, iteration_id
```


| Symbol | Meaning |
|---|---|
| $N_q$ | the q-irreducible wedge when `restart_q_storage` resolves to `ibz` (orbit-closed centroids and a reduced q grid), else every q point |
| $N_k$ | every k point of the grid |
| $N_p$ | the raw WFN parent k points |
| $N_b$ | the loaded band window, $b_4-b_0$ |
| $n_s$ | spinor components |
| $N_T$ | rows of `centroids_file_current` |
| $n_\omega$ | 1 for `cohsex` and `mpa` (the static $W$); 2 for `gn_ppm` and `hl_ppm` ($0$ and the probe) |

`W0_qmunu` is allocated as a zero placeholder with `W0_ready = false` when $V_\bq$ is written, and filled after screening. It stays a placeholder, with no head scalars, under `x_only` and under `mpa` with `sigma_w_model = mpa`; consumers refuse it. A QSGW run writes $W_0$ once, from the accepted map. On `restart = true` the bundle is not rewritten, but $W_0$ and the head scalars are refreshed in place. The head scalars are described in [Stored head scalars](../../theory/q0-head.md#bse-scalars); `W0_lr/` holds the long-range channels of the static Dyson route.

## zeta_q.h5 {: #zeta }

`isdf_fitting.fit_zeta_to_h5`
{: .in-code }

```tree
tmp/zeta_q.h5
  lorrax_io_committed              int32[1]
  mf_header/                       copied verbatim from WFN.h5
  isdf_header/
    density                        bytes            scalar | current
    vertex_mu_L                    int32            0 charge, 1-3 current
    zeta_is_done                   bool             false until the last block lands
    zeta_layout                    bytes            G_flat
    centroids/
      r_mu_fft_idx                 int32[N_mu, 3]
      r_mu_crystal                 float64[N_mu, 3]
    gvec_components                int32[N_q, 3, ngkmax]
    ngk                            int32[N_q]
    zeta_cutoff_ry                 float64
    fit_provenance                 bytes            JSON, schema 2
  zeta_q_G                         complex128[N_q, N_mu, ngkmax]    zero past ngk[q]
```

$N_q$ is the q-irreducible wedge when the centroid set is orbit-closed, else every q point; the G sphere is $|\bq+\bG|^2\le$ `zeta_cutoff`. The file is not named by $N_\mu$: two runs in one directory share it.

## Shared-pole and MPA stores {: #mpa-stores }

`shared_pole_store.write_shared_pole_model`
{: .in-code }

With `sigma_w_model = shared_pole`, each screening build writes `tmp/mpa/<label>_shared_pole/`, where `<label>` is `oneshot` or `sc_<NNNN>`. Its `model.h5`, schema `lorrax.shared-real-pole.v1`, holds $W^c_\bq(\mu,\nu;z)=\sum_j b_{j\bq}(\mu)b^*_{j\bq}(\nu)\big[(z-\Omega_{j\bq})^{-1}-(z+\Omega_{j\bq})^{-1}\big]$, with $b$ normalised as in [Shared-pole W §2.1](../../theory/shared-pole-w.md#model-form):

```tree
tmp/mpa/<label>_shared_pole/model.h5
  lorrax_io_committed              int32[1]
  header_json                      bytes            canonical JSON: identity, recipe, digest, ...
  final_commit                     bytes            header digest; present once complete
  factor                           complex128[N_q, N_mu, c, K_max]   sqrt(2 Omega) b, Ry^(3/2); zero past K[q]
  poles2_ry2                       float64[N_q, K_max]               Omega^2, Ry^2
  K                                int64[N_q]       active poles per q
  written_q                        int8[N_q]
  q_irr_full_idx                   int64[N_q]
  qirr/                            irr_idx_q sym_idx_q sym_perm L_table q_irr_frac n_sym_spatial
  operations/                      rows rotation authorized_rows antiunitary translation spin_real spin_imag
```

$N_q$ is the q-irreducible wedge; $c$ is 1 on the charge route. `factor` holds $\sqrt{2\Omega_{j\bq}}\,b_{j\bq}(\mu)$, so $b_{j\bq}=\texttt{factor}/\sqrt{2\Omega_{j\bq}}$ with $\Omega_{j\bq}=\sqrt{\texttt{poles2\_ry2}}$. The directory also holds JSON receipts (`bank_receipt.json`, `constructor_receipt.json`, `construction_receipt.json`, and `head_receipt.json` with the head on), and on the four-current routes `sectors.json` with `CC.h5`, `TT.h5`, `CT_C.h5`, `CT_T.h5`, `constant.h5`. A QSGW run keeps only the current map's directory. `write_poles = true` exports `tmp/mpa/<label>_poles.h5` (the same tree plus `mf_header/`, `poles_header/` and `b`, a link to `factor` that therefore also holds $\sqrt{2\Omega}\,b$); `write_w = true` exports the response bank as `tmp/mpa/<label>_w.h5`.

With `sigma_w_model = mpa` the elementwise fit writes `tmp/mpa/mpa_samples_<label>.h5` (`chi_qmunu_z`, `Wc_qmunu_z`, complex128[$n_\omega$, $N_q$, $N_\mu$, $N_\mu$]) and `tmp/mpa/mpa_fit_<label>.h5` (`Omega_p`, `B_p`, complex[$n_p$, $N_q$, $N_\mu$, $N_\mu$], and `fit_condition`, with `B_p` the residue $R_{j\bq}(\mu,\nu)$ itself), each stamped with its frequency grid, WFN and charge-ζ identity. A completed fit is write-once unless `mpa_overwrite_completed_artifacts = true`.

## sigma_mnk.h5 {: #sigma-mnk }

`sigma_output.write_sigma_omega_h5`
{: .in-code }

Written in `gn_ppm`, `hl_ppm` and `mpa`; `cohsex` and `x_only` write none. Energies are in eV, and the `*_rel_ev` axes are relative to `omega_reference_ev`. The cubes are on the star wedge, one row per symmetry star, with the unfold tables beside them; the eqp receipt is on the WFN wedge. Tree of the default on-shell layout:

```tree
sigma_mnk.h5
  lorrax_io_committed                  int32[1]
  eqp_assembly_receipt_expected        int32            5, or 6 with a transverse field
  sigma_evaluation                     bytes            on_shell
  irr_idx_k                            int32[N_k]
  sym_idx_k                            int32[N_k]
  sigma_total_kij_ev                   complex128[2, N_s, N_b, N_b]    @pair_slots @k_storage ...
  sigma_c_kij_ev                       complex128[2, N_s, N_b, N_b]
  onshell_<table>_rel_ev               float64[N_s, N_b]               table = pair, eval0, dft0 (+ zero, edge: QSGW, sigma_out_of_grid = static)
  sigma_c_onshell_<table>_kn_ev        complex128[N_s, N_b]
  sigma_c_onshell_dsigma_kn            complex128[N_s, N_b]            exact dSigma^c_nn/dw
  sigma_sx_kij_ev                      complex128[N_s, N_b, N_b]       bare Sigma^x
  hartree_kij_ev                       complex128[N_s, N_b, N_b]
  [hartree_scalar_kij_ev]              complex128[N_s, N_b, N_b]       transverse field only
  [hartree_transverse_kij_ev]          complex128[N_s, N_b, N_b]
  sigma_eval_rel_ev                    float64[N_s, N_b]               @sigma_eval_provenance @omega_uncovered_count ...
  [sigma_c_extrap_{inf,last,sigma}_kn_ev]   complex128[N_s, N_b]       band extrapolation
  [sigma_c_extrap_beta_kn]             complex128[N_s, N_b]
  [eqp_assembly_conditioned_diagonals_ev]          complex128[3, N_w, N_b]   H, X, C(E_DFT); one-shot
  [eqp_assembly_conditioned_sigma_c_onshell_ev]    complex128[4, N_w, N_b]   C(E_DFT), C(E_eval), dC/dw, coverage
  [eqp_assembly_hartree_scalar_transverse_diag_ev] float64[2, N_w, N_b]
  [sigma_xc_qsgw_kij_ev]               complex128[N_s, N_b, N_b]       write_qsgw_datasets
  [qp_omega0_ev]                       float64[N_s, N_b]               write_qsgw_datasets, grid layout
```

Slot 0 of the pair is $\Sigma_{mn}(E_m)$, slot 1 is $\Sigma_{mn}(E_n)$, and `sigma_total_kij_ev` is $\Sigma^c+\Sigma^x+V^{\mathrm H}$. `onshell_pair_rel_ev` carries `omega_reference_ev`, its provenance, and the effective and requested `sigma_regularization_ev`. With `sigma_omega_grid_debug = true` the file instead holds `omega_ev` float64[$N_\omega$], the cubes as complex128[$N_\omega$, $N_s$, $N_b$, $N_b$], no `sigma_evaluation` and no `onshell_*` sets, and the receipt curve `eqp_assembly_conditioned_sigma_c_omega_diag_ev` complex128[$N_\omega$, $N_w$, $N_b$]. A QSGW run writes the file once after convergence, in the accepted map's QP basis, without the eqp receipt; the file does not record that basis beyond `sigma_eval_provenance = self_consistent_qp`.

## qp_wfn_rotations.h5 {: #rotations }

`qp_wfn.write_qp_rotations_h5`
{: .in-code }

```tree

  E_qp_nk_rydberg                  float64[N_k, N_b]           Ry
  [E_full_nk_rydberg]              float64[N_k, N_all]         QSGW with smeared occupations

  [sc_seed_policy/]                protected_mask_kn, in_range_mask_kn      QSGW
  band_range                       int32[2]                    [b0, b3), 0-based
  kpoints_crys                     float64[N_kfull, 3]
  kgrid                            int32[3]
  kpoints_reduced                  float64[N_w, 3]
  kirr_to_kfull                    int32[N_w]
  [irr_idx_k, sym_idx_k]           int32[N_kfull]              wedge storage only
  @source_wfn_fingerprint_scheme   str
  @source_wfn_fingerprint          str                         64-hex SHA-256
  @description @energy_units @band_convention @mapping_description
  [@qp_solver @qp_energy_definition @sigma_eval_provenance]    one-shot only
  [@qp_wfn_occ_hash @qp_wfn_occ_mu_ry ...]                     with occupations
```

$N_k$ is $N_{k\mathrm{full}}$, or the WFN wedge $N_w$ when `qp_rotations_k_storage` reduces it; the reduced datasets then carry `@k_storage = ibz`. `auto` reduces only when the unfold reproduces every full-zone row exactly, which a one-shot run's per-k eigensolve does not, so one-shot files are normally full-zone. The file is plain HDF5 with no commit flag. A QSGW run also writes `sc_seed/qp_wfn_rotations.h5` after each non-converged map.

## WFN_qp.h5 {: #wfn-qp }

`qp_wfn.write_qp_wfn_h5`
{: .in-code }

A BerkeleyGW `WFN.h5` on the source WFN's k set, symmetry and G lists. On the active bands $[b_0,b_3)$ the coefficients are $c^{\mathrm{QP}}_{n}=\sum_m U_{\bk,mn}c^{\mathrm{DFT}}_m$ and `mf_header/kpoints/el` holds $E^{\mathrm{QP}}$; other bands keep their coefficients and mean-field energies (QSGW: the tail scissor). `mf_header/kpoints/occ` is a step table, or a QSGW run's fixed-$N$ smeared table; `ifmax` is always the step. Root attributes mark it: `@qp_wfn_scheme = lorrax-qp-wfn-v1`, `@qp_wfn_band_start`, `@qp_wfn_band_stop`, `@qp_wfn_source`, and the solver or occupation stamps. Consumers read these stamps to refuse a second QP correction on top.

A one-shot run writes it only when Σ's k set is the WFN's own: on a symmetry-reduced WFN the one-shot Σ is on the full zone, and the file is skipped with a message. QSGW runs write it on the WFN wedge.

## Bispinor files {: #bispinor }

A bispinor run adds `tmp/zeta_q_mu1.h5`, `tmp/zeta_q_mu2.h5`, `tmp/zeta_q_mu3.h5` (the [zeta_q.h5](#zeta) tree, `density = current`, $N_T$ rows), the transverse entries of the [restart bundle](#restart), and `tmp/v_q_bispinor.h5`:

```tree
tmp/v_q_bispinor.h5
  lorrax_io_committed              int32[1]
  kgrid                            int64[3]
  n_rmu_C  n_rmu_T  n_q_total      int64
  V_qmunu_CC                       complex128[N_q, N_mu, N_mu]
  V_qmunu_TT_<ij>                  complex128[N_q, N_T, N_T]    ij = 11 22 33 12 13 23
  V_qmunu_*__qirr/                 q-wedge unfold tables
  photon_g0_vectors_<c>            complex128[1, N_mu or N_T]    c = 0..3
  v_qmunu_generation_receipt       str              JSON policy + generation id
  v_qmunu_format                   bytes            bispinor_lorentz_v2
  v_qmunu_unique_tile_inventory    bytes
  v_qmunu_data_ready               bool             set last
  @unique_tiles @zero_tiles @hermitian_pairs
```

The zero tiles $(0,i)$, $(i,0)$ and the Hermitian partners $(j,i)$ are not stored. With `sigma_lorentz_debug_output = true`, a QSGW run also writes `<run>/sigma_lorentz_iter<NNNN>.h5` with the CC, CT+TC and TT matrices of each map.

The QSGW per-map and continuation files, `eqp0_iter<NNNN>.dat`, `sc_seed/`, `sc_checkpoint.h5` and `dipole_qsgw.h5`, are described in [Terminal files](../../theory/qsgw.md#out-files).
