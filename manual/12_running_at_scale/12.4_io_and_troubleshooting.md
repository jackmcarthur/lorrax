# 12.4 Parallel I/O; troubleshooting

`slab_io` selects how the large HDF5 datasets are written: `phdf5` (MPI-IO, every
rank writes its shard concurrently; the cluster default when the FFI is built),
`phdf5_host` (the same via host MPI on the CPU backend), and `allgather`
(gather-to-rank-0; correct everywhere, the single-node default). `gspace_io`
routes the per-q ζ reads similarly. The ζ store's layout puts the centroid axis
innermost so both the fit's chunk writes and $V_q$'s per-q reads are contiguous.

Troubleshooting, most common first:

| Symptom | Cause and fix |
|---|---|
| OOM in the fit kernel | read the planner block (§12.2); more devices, or smaller band window |
| minutes-long "writing" phases at scale | `slab_io` fell back to `allgather`; build the FFI (§2.3) |
| exchange energies off by tens of meV vs BGW | cutoff conventions (§6.3); then App. E checklist |
| large LORRAX-vs-BGW residual that plateaus with $n_\mu$ | not the basis; conventions (App. E) |
| first run stalls minutes before output | XLA compilation; set `JAX_COMPILATION_CACHE_DIR` |
| hang at a distributed factorization | mesh geometry limit (§12.3); check the startup banner |
| plasmon-pole census reports a large invalid fraction | metallic or near-metallic screening; §7.4, consider static COHSEX |
