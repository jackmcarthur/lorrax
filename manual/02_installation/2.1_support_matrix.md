# 2.1 Dependencies

To run LORRAX, one must have Python ≥ 3.12 and JAX ≥ 0.9 installed on the cluster
and built against the CPU/GPU compute node architecture; many research clusters have documentation on a preferred way to do this, often using a Shifter container. GPUs should have CUDA-13. The `jax[cuda13]` wheels bundle the CUDA
runtime, so a bare virtual environment from `uv sync` is a complete install
(§2.2); sites that discourage user Python environments run the same source in the
NVIDIA JAX container image (§2.4). Remaining Python dependencies are declared in
`pyproject.toml` and installed automatically.

JAX is a Python-based package for distributed scientific computing and machine
learning research. It has built-in capabilities for operations on
distributed arrays, e.g. multiplying two matrices that are each divided among
memory on a grid of processors. Code written against its NumPy-like interface is
compiled to fused kernels for the local architecture with interprocessor
communication inserted automatically, so a single Python source expresses the whole
pipeline with no hand-written CUDA or MPI (Ch. 13). However, JAX does not currently
support every distributed I/O and linear algebra routine used in contemporary electronic
structure codes, such as matrix inversion and Cholesky decomposition of
distributed matrices, or parallel writes of large output files. For this reason, LORRAX has features to call lower-level libraries supplying these routines, collected in one
native library reached through JAX's foreign-function
interface and selected at runtime from available backends and/or the input file. 

The recommended installation is with the parallel HDF5 library for I/O and
cuSOLVERMp for distributed linear algebra on Nvidia GPU clusters, or SLATE on
other GPU or CPU clusters. None are required: without them LORRAX falls back to
serial I/O and single-device linear algebra, correct but slow beyond roughly one
node, and an explicitly requested backend that is missing fails with the build
command rather than falling back silently.

| Optional dependency | Function | Input keys |
|---|---|---|
| parallel HDF5 (MPI-IO) | concurrent sharded writes of ζ, Σ(ω), and restart files | `slab_io` |
| cuSOLVERMp + CAL | distributed Cholesky, LU, and eigendecomposition on NVIDIA GPUs | `distributed_cholesky`, `distributed_lu` |
| cuBLASMp | distributed matrix multiplication and the fused screening solve | `screening_solver` |
| SLATE (+ blaspp, lapackpp) | the same dense linear algebra, portable across GPU and CPU clusters | `distributed_cholesky = slate`, `distributed_lu = slate` |

Acquisition and build recipes for each: §2.3.
