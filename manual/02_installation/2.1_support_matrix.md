# 2.1 Dependencies

To run LORRAX, one must have Python ≥ 3.12 and JAX ≥ 0.9 installed on the cluster
and built against the CPU/GPU compute node architecture, whether in a Shifter image
or natively. GPUs should have CUDA-13. The `jax[cuda13]` wheels bundle the CUDA
runtime, so a bare virtual environment from `uv sync` is a complete install
(§2.2); sites that discourage user Python environments run the same source in the
NVIDIA JAX container image (§2.4). Remaining Python dependencies are declared in
`pyproject.toml` and installed automatically.

JAX is a Python-based package for distributed scientific computing and machine
learning research which has a number of capabilities for performing operations on
distributed arrays, e.g. multiplying two matrices that are each divided among
memory on a grid of processors. Code written against its NumPy-like interface is
compiled to fused kernels for the local architecture with interprocessor
communication inserted automatically, so a single Python source expresses the whole
pipeline with no hand-written CUDA or MPI (Ch. 13). However, JAX does not currently
support every distributed I/O and linear algebra routine used in electronic
structure codes today, e.g. matrix inversion and Cholesky decomposition of
distributed matrices, or parallel writes of large output files. So we provide
interfaces to lower-level libraries supplying these routines, collected in one
native library (`liblorrax_ffi.so`, §2.3) reached through JAX's foreign-function
interface and selected at runtime from the input file.

The preferred installation is with the parallel HDF5 library for I/O and
cuSOLVERMp for distributed linear algebra on Nvidia GPU clusters, or SLATE on
other GPU or CPU clusters. None are required: without them LORRAX falls back to
serial I/O and single-device linear algebra, correct but slow beyond roughly one
node, and an explicitly requested backend that is missing fails with the build
command rather than falling back silently.
