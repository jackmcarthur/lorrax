# 2.1 Dependencies

To run LORRAX, one must have Python ≥ 3.12 and JAX ≥ 0.9 installed on the cluster
and built against the CPU/GPU compute node architecture, whether in a Shifter image
or natively. GPUs should have CUDA-13. The `jax[cuda13]` wheels bundle the CUDA
runtime libraries, so on nodes with a recent NVIDIA driver a bare virtual
environment created by `uv sync` is a complete install (§2.2); sites that
discourage user Python environments run the same source inside the NVIDIA JAX
container image under Shifter or Apptainer (§2.4). The remaining Python
dependencies (NumPy, SciPy, h5py) are declared in `pyproject.toml` and installed
automatically.

JAX is a Python-based package for distributed scientific computing and machine
learning research which has a number of capabilities for performing operations on
distributed arrays, e.g. multiplying two matrices that are each divided among
memory on a grid of processors. Functions written against its NumPy-like interface
are compiled to fused kernels for the local CPU or GPU architecture, with the
interprocessor communication inserted by the compiler, which is what lets a single
Python source express the whole GW pipeline with no hand-written CUDA or MPI
(Ch. 13). However, JAX does not currently support every distributed I/O and linear
algebra routine used in electronic structure codes today: it has no distributed
dense Cholesky, LU, or eigendecomposition, so a matrix divided among many
processors must be gathered to one device before factorization, and it performs no
parallel file I/O, so the multi-GB ζ and Σ(ω) datasets would be written through a
single rank in serial. So we provide interfaces to lower-level compiled libraries
supplying exactly these routines, collected in one native library
(`liblorrax_ffi.so`, built once per machine, §2.3) that JAX reaches through its
foreign-function interface, with the backend for each task selected at runtime
from the input file (`slab_io`, `distributed_cholesky`, `distributed_lu`,
`screening_solver`, all defaulting to `auto`).

The preferred installation is with the parallel HDF5 library for I/O and
cuSOLVERMp for distributed linear algebra on Nvidia GPU clusters, or SLATE on
other GPU or CPU clusters. None of these are required: without them LORRAX falls
back to serial I/O and single-device factorizations, correct at any scale but slow
beyond roughly one node, and a backend requested explicitly in the input file that
is missing fails with the build command in the error message rather than falling
back silently.
