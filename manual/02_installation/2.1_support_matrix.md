# 2.1 Dependencies

Two layers. The pure-Python layer (Python ≥ 3.12, JAX ≥ 0.9 with the CUDA-13 extra
as default GPU target, NumPy/SciPy, h5py) runs every physics feature on CPU or GPU
within a single process; `uv sync` is the entire install. The native FFI layer
(`liblorrax_ffi.so`) adds the collective backends:

| Library | Provides | Input keys |
|---|---|---|
| parallel HDF5 (MPI-IO) | sharded ζ / Σ(ω) / restart I/O | `slab_io` |
| cuSOLVERMp + CAL, cuBLASMp | distributed Cholesky/LU/eigh, fused W solve | `distributed_cholesky`, `distributed_lu`, `screening_solver` |
| SLATE (+ blaspp/lapackpp) | the same dense operations, portable CPU/GPU | `distributed_cholesky = slate`, ... |

A fresh clone has no `liblorrax_ffi.so` (gitignored build artifact). The pure layer
never touches it; the first distributed call without it fails with the build command
in the error message. Every optional dependency follows this contract: a requested
backend that is missing is a loud error, never a silent fallback.

`pyproject.toml` is authoritative for Python-side pins; site scripts and container
images can lag it.

| Configuration | Layer | Status |
|---|---|---|
| CPU-only, bare venv | 1 | supported (CI path) |
| Single GPU / one node | 1 | supported |
| Multi-node cluster | 1 + 2 | supported; layer 2 strongly recommended (§2.3) |
| NERSC Perlmutter | 1 + 2 | reference platform, validated continuously (§2.4) |
