# 2.1 What you need: the two-layer picture

LORRAX has deliberately few *hard* dependencies and a small set of *optional native*
ones — and the difference between a workstation install and a cluster install is
entirely in the second set.

**Layer 1 — the pure-Python core.** Python ≥ 3.12 plus the packages `pyproject.toml`
declares: JAX (≥ 0.9; the default GPU extra targets CUDA 13), NumPy/SciPy, h5py,
matplotlib, and the XML-schema readers used for pseudopotential parsing. This layer
runs *every* physics feature of the code — the full GW pipeline, BSE, band
interpolation — on CPU or on GPUs, on one device or several within a single process.
Nothing needs compiling; `uv sync` (or `pip install -e .`) is the entire install.

**Layer 2 — the native FFI stack** (`liblorrax_ffi.so`), which provides three things
the pure layer replaces with slower fallbacks:

| Native library | What it accelerates | Input keys that engage it |
|---|---|---|
| parallel HDF5 (MPI-IO) | sharded reads/writes of ζ, Σ(ω), restart files | `slab_io` |
| cuSOLVERMp (+ CAL) / cuBLASMp | distributed Cholesky/LU/eigh, fused W-solve across GPUs | `distributed_cholesky`, `distributed_lu`, `screening_solver` |
| SLATE (+ blaspp/lapackpp) | the same dense operations, portable CPU/GPU alternative | `distributed_cholesky = slate`, … |

A fresh clone contains **no** `liblorrax_ffi.so` — it is a gitignored build artifact.
The pure layer never touches it (all FFI imports are lazy); the first call into a
distributed feature without it fails loudly with the build command in the error
message. That loud-failure contract holds for every optional dependency: a requested
backend that is missing is an error with instructions, never a silent fallback.

**Version truth.** `pyproject.toml` is authoritative for the Python-side pins
(currently `jax[cuda13]>=0.9.0`, Python ≥ 3.12); site documents and container images
can lag behind it. When this manual and a site script disagree, trust `pyproject.toml`
and the error messages.

| Configuration | Layer | Scale | Status |
|---|---|---|---|
| CPU-only, bare venv | 1 | serial / testing | supported (the CI path) |
| Single GPU workstation | 1 | 1 GPU | supported |
| One node, several GPUs | 1 (2 recommended) | ≤ 4–8 GPUs | supported |
| Multi-node cluster | 1 + 2 | arbitrary | supported — **layer 2 strongly recommended** (§2.3) |
| NERSC Perlmutter | 1 + 2 | reference platform | validated continuously (§2.4) |
