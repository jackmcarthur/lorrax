# 2.3 Cluster tier: parallel I/O and distributed linear algebra

Parallel HDF5: engaged by `slab_io` (auto-selected when available); every rank
writes its own shard of ζ, Σ(ω), and restart data. Obtain from conda-forge
(`hdf5=*=mpi_*`), spack (`hdf5+mpi`), or `cray-hdf5-parallel` plus the provided
stage script. The CMake build enforces `HDF5_IS_PARALLEL`; serial HDF5 is rejected.

cuSOLVERMp + CAL (and cuBLASMp): distributed Cholesky/LU/eigh and the fused W solve
on NVIDIA GPUs, engaged by `distributed_cholesky` / `distributed_lu` /
`screening_solver` (defaults `auto`). Easiest acquisition:

```bash
pip install nvidia-cusolvermp-cu12==0.7.2.888 nvidia-cal-cu12
```

The pin matters: 0.6.0 silently returns wrong answers on process meshes with both
dimensions > 1. The build accepts `-DCUSOLVERMP_INCLUDE_DIR/-DCUSOLVERMP_LIB_DIR`
pointed at the wheel, an NVHPC SDK, or a spack install.

SLATE (+ blaspp/lapackpp): the portable alternative for the same operations,
including on CPU nodes, selected per operation from the input file
(`distributed_cholesky = slate`). Built from source via the provided scripts.

```bash
bash src/ffi/common/cpp/build.sh      # produces liblorrax_ffi.so
```

Validate with `tests/test_ffi_linalg_contract.py` (skipif-gated, ~19 s, exercises
every backend × mesh × dtype it finds). Backend keys set to `auto` use the native
path when present and the pure path when absent; a key set explicitly that cannot
be honored is a hard error naming the missing library. Known vendor-library failure
geometries (non-square meshes for some operations) are rejected with explanatory
errors rather than hangs (§12.3). MPI comes from the same one-process-per-GPU
launch the pure tier uses (§12.1).
