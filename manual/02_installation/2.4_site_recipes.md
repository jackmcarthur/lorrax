# 2.4 Site recipes

NERSC Perlmutter (reference platform, 4× A100 nodes, Cray MPICH, Shifter):

```bash
export LX_BASE_MODULE=lorrax_A
export LORRAX_CHECKOUT=$PWD
SOURCE_PATH="$LORRAX_CHECKOUT/src${PYTHONPATH:+:$PYTHONPATH}"
lx doctor --refresh
lx run -N 1 -G 4 -n 4 -- env PYTHONPATH="$SOURCE_PATH" \
  python3 -u -m centroid.kmeans_cli 640 --seed 42
lx run -N 1 -G 4 -n 4 -- env PYTHONPATH="$SOURCE_PATH" \
  python3 -u -m psp.get_dipole_mtxels -i cohsex.in
lx run -N 1 -G 4 -n 4 -- env PYTHONPATH="$SOURCE_PATH" \
  python3 -u -m gw.kin_ion_io -i cohsex.in
lx run -N 1 -G 4 -n 4 -- env PYTHONPATH="$SOURCE_PATH" \
  python3 -u -m gw.gw_jax -i cohsex.in
```

`lx` allocates or attaches, enforces one task per GPU, enters the site image,
and stages native libraries. The payload-side source path selects the checkout;
the runtime source-closure receipt attests its first-party services. Details are
in `docs/environment/machines/perlmutter.md` and `config/README.md`.

On another Slurm site, install a site descriptor instead of copying a bare
`sbatch` header: the container/native/MPI closure is machine-specific. Preserve
the same one-process-per-GPU geometry and route through the machine page in
`docs/environment/`.

Container users (Apptainer/Singularity, `--nv`) bind-mount the source tree and
library prefixes; the Shifter path in `config/` is the worked example.

Workstation: `uv sync` and go (§2.2). Set `memory_per_device_gb` to VRAM minus
~2 GB headroom; the memory planner (§12.2) reports when a system has outgrown the
card.
