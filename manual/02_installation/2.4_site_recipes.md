# 2.4 Site recipes

## NERSC Perlmutter (reference platform)

Perlmutter is the continuously validated platform (4× A100 nodes, Cray MPICH,
Shifter). LORRAX ships a site module that wraps allocation, preprocessing, and
launch:

```bash
# one-time
vi config/perlmutter/site_config.sh    # account, QoS, paths
bash config/perlmutter/install.sh      # installs the Lmod module

# every session
module load lorrax
lxalloc                                # interactive: 1 node / 4 GPUs, exports SLURM_JOBID
lxpre cohsex.in 640                    # preprocessing: centroids + dipole.h5 + kin_ion.h5
lxrun python3 -u -m gw.gw_jax -i cohsex.in
```

`lxrun` handles the process-per-GPU `srun` invocation, container bind-mounts, and the
staged native libraries. Site specifics (queues, bind-mount contract, multi-checkout
setups) live in `config/README.md` in the repository.

## Generic SLURM cluster

The shape of any launch is: **one process per GPU**, JAX distributed initialization
from the SLURM environment, native libraries on `LD_LIBRARY_PATH` if built.

```bash
#SBATCH --nodes=2
#SBATCH --ntasks-per-node=4        # = GPUs per node
#SBATCH --gpus-per-node=4

srun python3 -u -m gw.gw_jax -i cohsex.in
```

No LORRAX-specific environment beyond the Python environment of §2.2 is required for
the pure tier; the cluster tier additionally needs the §2.3 libraries visible at run
time. Container users (Apptainer/Singularity with `--nv`) bind-mount the source tree
and library prefixes; the Shifter path in `config/` is the worked example of the
same contract.

## Workstation

`uv sync` and go (§2.2). A single GPU runs the tutorial systems in minutes; the
memory planner (§12.2) will tell you when a system has outgrown the card — set
`memory_per_device_gb` to your VRAM minus ~2 GB headroom.
