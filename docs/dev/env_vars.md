# LORRAX environment variables — the registry

*Every environment variable LORRAX reads, where it is read, what it
defaults to, and whether it should still be an env var at all.*

Generated by auditing every `os.environ` / `os.getenv` / `getenv()` read
under `src/` (Python **and** C++) on 2026-07-25 and cross-checking the
defaults at each site.

## How to read this page

The **Scope** column is the important one:

| scope | meaning |
|---|---|
| **runtime** | read by the running code; affects a production run. |
| **debug** | diagnostics only — printing, dumping, timing. Never changes numerics. |
| **build** | read by `config/**/*.sh` / CMake at BUILD time. Never read by the Python at runtime. |
| **deprecated** | superseded by an input-file key; still honoured, prints a notice. |
| **external** | not ours — JAX / SLURM / MKL / HDF5. Listed only where LORRAX sets or depends on it. |

**Rule of thumb, and the reason this page exists:** an env var is
acceptable for *machine* facts (where a library lives, how many ranks,
which fabric) and for *debug* switches. It is the wrong home for a
*physics* knob — those belong in `cohsex.in`, where they are parsed,
validated, echoed into the run log, and captured by provenance. Three
current entries violate that; they are called out in
[Promotion candidates](#promotion-candidates).

## 1. Runtime — physics / numerics

These change the numbers a run produces.

| var | default | effect |
|---|---|---|
| `LORRAX_ZETA_RCOND` | input key `zeta_rcond` | Relative cutoff for the rank-revealing pseudo-inverse in the replicated ζ solve (`isdf/core.py:1279`). Env **overrides the input key**. Production value 1e-8. This is THE conditioning knob of the μ ladder — see [Promotion candidates](#promotion-candidates). |
| `LORRAX_ZETA_RIDGE` | input key `zeta_ridge` | Additive ridge on `C_q` before the ζ factorization (`isdf/core.py:1278`). Env overrides the key. |
| `LORRAX_ZETA_REPLICATE_CAP_GIB` | `4` | Byte cap (GiB) on the `(nq, n_μ, n_μ)` c128 stack below which the charge factor is fully **replicated** and therefore mesh-invariant (`isdf/core.py:945`). Above the cap `rank_truncate` REFUSES rather than downgrading. Raising this is a memory-vs-invariance trade, not a free knob. |
| `LORRAX_FORCE_FULL_BZ` | `0` | `1` disables IBZ-only ζ writes; ζ is written for the full BZ. Read at 5 sites (`gw_init.py` ×3, `screening.py`, `v_q_g_flat.py`) — all with the same `'0'` default. |
| `LORRAX_EXTRA_MU_PAD` | `""` (→ 0) | **Test-only.** Adds slack to the padded μ extent to prove pad-extent invariance (`runtime/padding.py:58`). Any result that moves under this at fixed P is a defect. NEVER set in production. |
| `LORRAX_FORCE_REFIT` | `""` (off) | `1` forces the ζ fit even when `tmp/zeta_q.h5` is complete and its provenance matches (`gw_init.py`). Escape hatch for the ζ-reuse cache. |
| `LORRAX_MAX_RCHUNKS` | unset | Ceiling on the r-chunk count the planner may pick (`isdf_fitting.py:933`). Memory/perf, not numerics — but it changes the chunking, which the 2026-07 scale ladder showed is load-bearing at large μ. |
| `ISDF_CHUNK_TARGET_UTILIZATION` | `0.0` (auto) | Overrides the planner's memory-utilization target; clamped to [0.85, 1.0] (`gw_config.py:1185`). |
| `ISDF_ZCT_STAGE_CAP_GB` | unset | Absolute cap (GB) on the ζ-contraction stage transient (`gw_config.py:1194`). |
| `ISDF_ZCT_STAGE_CAP_FRAC` | unset | Same cap as a fraction of the per-device budget (`gw_config.py:1195`). |
| `LORRAX_TRS_CHECK` | `1` (ON) | Load-time MEASUREMENT of the WFN's symmetries against the density built from its own occupied ψ (`common/density_symmetry_check.py:trs_check_mode`, called from `file_io/wfn_loader.py` `_run_density_symmetry_check`). `0` disables it and restores the pre-2026-07 flags-only behaviour; `strict` raises instead of warning. The measured `trs_holds` verdict GATES `SymMaps`'s time-reversal augmentation — with the check off, a magnetic deck can again be silently time-reversed (scorecard §Q class of bug). Not a physics knob in the input-key sense: it selects whether a *diagnostic* runs, and its default is on. |
| `LORRAX_TRS_TOL` | `1e-6` | Relative tolerance on `‖Σ_pair w·m‖∞ / ‖ρ‖∞` for the TRS verdict (`density_symmetry_check.py:TOL_TRS`). Measured residuals on every LORRAX fixture are ≤ 1e-12; real magnetization is O(1e-2…1). |
| `LORRAX_TRS_SPATIAL_TOL` | `1e-4` | Relative tolerance on `‖ρ(Sr+τ) − ρ(r)‖∞ / ‖ρ‖∞` per claimed symmetry op (`density_symmetry_check.py:TOL_SPATIAL`). A wrong op mismatches by O(0.1…1). |
| `LORRAX_TRS_MAX_K` | `32` | Cap on the k-points sampled by the check; `0` = all. The sample is ±-closed, so it is a *sufficiency* choice, not an approximation: every ± pair is an independent exact identity under TRS. |

## 2. Runtime — I/O, backends, placement

Machine and library facts. Legitimately env vars.

| var | default | effect |
|---|---|---|
| `LORRAX_FFI_SO` | in-tree `src/ffi/common/cpp/build/liblorrax_ffi.so` | Path to the **CUDA** FFI library (`ffi/common/ffi_loader.py:96`). |
| `LORRAX_FFI_HOST_SO` | in-tree `src/ffi/common/cpp/host/build/liblorrax_ffi_host.so` | Path to the **host** FFI library (`ffi_loader.py:103`). Point this at `$WORK/lorrax_ffi_unified/build_host/…` for the SLATE+ScaLAPACK build. |
| `LORRAX_WFN_BACKEND` | `""` (→ config/auto) | Forces the WFN read backend: `eager` \| `phdf5` \| `phdf5_host` (`file_io/wfn_loader.py:277`). |
| `ISDF_JAX_CACHE_DIR` | `$XDG_CACHE_HOME/isdf_jax_compilation` (→ `~/.cache/...`) | JAX persistent compile-cache dir (`common/jax_compile_cache.py`). `""` opts out entirely. **At `jax.process_count() > 1` the cache is now REFUSED in-tree and the reason printed** — you no longer have to remember this in the launcher (scorecard AG). Root cause: JAX writes cache entries from **process 0 only** (`jax/_src/compiler.py::_cache_write`), so the peers' per-rank dirs stay empty forever; process 0 then hits and skips compilation while the peers block in `xla::gpu::AutotunerPass` → `MultiProcessKeyValueStore` → `CoordinationServiceAgent::GetKeyValue`, i.e. a permanent silent hang. Also note the container's default AOT cache is machine-mismatched (SIGILL risk). |
| `LORRAX_JAX_CACHE_MULTIPROCESS` | `0` (off) | Re-arms the persistent compile cache at P > 1, i.e. **re-arms the scorecard-AG deadlock**. Only for whoever is fixing the underlying process-0-only-write asymmetry (`common/jax_compile_cache.py`). |
| `LORRAX_MINIMAX_CACHE_DIR` | package dir | Where minimax grid tables are cached (`gw/minimax_screening.py:69`). |
| `LORRAX_DISABLE_MINIMAX_DISK_CACHE` | `""` (off) | Disables that disk cache (`minimax_screening.py:67`). |
| `LORRAX_PHDF5_STRIPE_COUNT` | `16` | Lustre stripe count applied before `H5Fcreate`. Read at 3 sites (`_slab_io_ffi.py:365`, `_slab_io_mpi_host.py:165`, `isdf_fitting.py:637`) — **all `'16'`, consistent.** |
| `LORRAX_PHDF5_STRIPE_SIZE_FS` | `4M` | Lustre stripe size, same 3 sites, **all `'4M'`, consistent.** |
| `LORRAX_PHDF5_MPI_STACK` | `mpich` | Build+launch: which MPI the phdf5 FFI links/loads (`run_shifter.sh:42`). |
| `LORRAX_PHDF5_ALIGN_MB` | `4` | C++: `H5Pset_alignment` threshold, MiB; `0` disables. |
| `LORRAX_PHDF5_COLL_META` | `0` | C++: `1` re-enables collective metadata ops (default off is faster). |
| `LORRAX_PHDF5_CB_NODES` / `_CB_PER_NODE` / `_CB_BUFFER_SIZE` / `_CB_WRITE` / `_DS_WRITE` | MPI-IO defaults | C++: ROMIO collective-buffering hints. |
| `LORRAX_PHDF5_INDEPENDENT` | off | Independent instead of collective MPI-IO (host slab writer). |
| `LORRAX_FFI_PROFILE` | off | C++: per-call FFI timing. |

## Consistency audit

Every LORRAX-owned variable read at more than one site was checked for
default drift. **No inconsistencies found:**

| var | sites | defaults |
|---|---|---|
| `LORRAX_FORCE_FULL_BZ` | 5 | all `'0'` ✓ |
| `LORRAX_PHDF5_STRIPE_COUNT` | 3 | all `'16'` ✓ |
| `LORRAX_PHDF5_STRIPE_SIZE_FS` | 3 | all `'4M'` ✓ |
| `LORRAX_MEM_DEBUG` | 4 | all presence-test ✓ |
| `LORRAX_RCHUNK_DEBUG` | 2 | all presence-test ✓ |

The scanner also flags `JAX_PLATFORMS`, `CUDA_VISIBLE_DEVICES`,
`XLA_PYTHON_CLIENT_*` and `TF_GPU_ALLOCATOR` as having "multiple
defaults". Each is a `setdefault` (writer) paired with a plain `get`
(reader) — the intended pattern, not drift.

Re-run the audit with:

```bash
python3 tools/env_audit.py src        # AST walk; flags "MULTIPLE DEFAULTS"
grep -rn 'getenv(' src/ffi            # the C++ side, which the tool can't see
```

## Promotion candidates

Ranked. These are physics knobs living in the environment, where they
escape input-file validation, the run log, and provenance.

1. **`LORRAX_ZETA_RCOND` → input key `zeta_rcond` (already exists — make
   the env the deprecated override, not the primary).** Workstream M's
   recommendation. Today `isdf/core.py:1279` reads the env with the key's
   value as the *fallback*, so the env silently wins and nothing prints.
   This is the single most consequential number in the μ ladder: at
   μ=1998 it decides `n_keep ≈ 1015 / 1998` with no spectral gap, i.e. it
   sets the numerical rank of the pair-density space. A sweep run whose
   rcond came from an env var is a run whose central parameter is not in
   its own input file. Fix = the `_sc_env` pattern from §4: key is the
   source of truth, env overrides loudly.
2. **`LORRAX_ZETA_RIDGE` → `zeta_ridge`.** Same site, same shape of
   problem, smaller blast radius. Do it in the same change.
3. **`LORRAX_ZETA_REPLICATE_CAP_GIB` → a memory-section key.** It gates
   `rank_truncate` reachability (the route that carries the conditioning
   cure), so "which route did this run take" currently depends on an env
   var. Lower priority than 1–2 only because raising it is already a
   deliberate, logged act.
4. `ISDF_ZCT_STAGE_CAP_GB` / `_FRAC` / `ISDF_CHUNK_TARGET_UTILIZATION` →
   memory-section keys, for symmetry with `band_chunk_size` /
   `r_chunk_size` / `gflat_chunk_size`, which are already keys.
5. `LORRAX_WFN_BACKEND` → the `slab_io` / backend config section, so the
   read path is recorded alongside the write path.

**Do NOT promote:** anything in §3 (debug), §5 (build), or `ISDF_JAX_CACHE_DIR`
(a machine fact, and its mandatory-`""` status on this cluster belongs in
the job script, not the physics input).
