# Size campaign — ISDF window, capacity, and the GN-PPM fit arena (2026-07-29)

Branch `wsREL-isdf-window`. Full detail: `wk_REL/ladder_rung1_notes.md` R7.3-R36.

## Release blocker (fixed): ISDF centroid selection ignored the deck's window

`centroid/kmeans_cli._resolve_sigma_window` defaulted `n_cond = min(n_val,
nbands - n_val)`, clamping the pivoted-Cholesky prune window to `n_val`. On the
MoS2 deck that produced a **26x52** window for every centroid set ever built,
while `Sigma_c` consumes **1024x1024** (or 2048x2048 at 45 Ry).

A `26x52` window contains at most `26*52 = 1352` independent pair densities, so
the achievable selection rank is **mathematically capped at ~1352**. Measured
ranks asymptote to it and the deficiency deepens with mu:

    c10000 630/897 (70%) · c15000 860/1357 (63%) · c20000 1009/1824 (55%)
    c25000 1089/2289 (48%) · c30000 1138/2769 (41%)   [30 Ry, nb=1024]
    c13000 597/1166 (51%)                             [45 Ry, nb=2048]

Effect on results, same deck / same N / same weapons / same rcond, only the
prune window differing:

| prune window | selection rank | eqp0 | eqp1 |
|---|---|---|---|
| `(0,52)` old default | 630/897 | **0.3645** | **-0.3639** |
| `(0,256)` | 897/897 | **3.1350** | **3.0710** |
| `(0,1024)` full | 897/897 | **3.7227** | **3.4551** |

A ~2.8 eV error that passed EVERY gate in the suite (el_compare 1.9e-11 eV,
gate_h0 3.9e-5, W-Dyson residual 1.9e-14, TRS, and even bare `Sigma_X` to 0.03%
and the q->0 head fit to 0.026%). Two gates were added: a **centroid rank
assertion** (hard refusal, fail-CLOSED on unparseable input) and a **pinned
Sigma reference** (b256/c2475, eqp0 3.5819 / eqp1 3.2516, tol 1e-3), the latter
bit-exact across a commit range and with the FFI/sharded feature set on.

**CAVEAT: every big-mu result predating the fix is unusable.** Memory results
are unaffected.

## Capacity: the frontier and the GN-PPM fit arena

`usable mu < 24,933` at nb=1024, P=64. mu=24,933 OOMs, reproduced
byte-identically twice (`Out of memory allocating 79744204800 bytes`).

The object is **not** an array: `module_0914.jit__gn_ppm_fit_kernel`,
`allocation 35: size 74.27GiB, preallocated-temp`. Parameters/outputs are
correctly sharded `c128[16,3120,3120]`; the arena is **exactly 32.0x one tile**
at both mu=24,933 and mu=2,475, so the multiple is structural:

    arena = 32 * nq * mu^2 * 16 / P     (DOES scale with P)

`_gn_ppm_fit_kernel` is purely elementwise in q and its two reductions are exact
integer boolean counts, so **q-chunking is bit-exact by construction**
(`LORRAX_PPM_FIT_ARENA_GIB`, default 8 GiB; `q_block >= nq` takes the untouched
single-shot path). Arena 74.27 -> 4.64 GiB at mu=24,933. Gated bit-exact on the
Sigma reference on BOTH the single-shot and a forced `q_block=1` path.

**Chunking shrinks the UNIT, not the COUNT — still 32 live tiles; target is
< 10.** Two further source-level reductions (dropping a redundant defensive
mask on `ratio`; folding nested selects so the fallback operand loses its q
axis) are bit-exact and remove 46 full-tile instructions but **change the arena
by zero bytes**. That is the strongest available evidence that op-count is the
wrong lever: the next attempt must target the fusion barrier — 42 guard ops
(and/compare/select/real/abs/is-finite) sit OUTSIDE any kLoop fusion, each
materialising a full tile. ~6 of the 32 tiles are genuine; ~26 are artefacts.

**No guard was weakened, removed, or reordered.** One candidate was rejected on
a distinction worth preserving: `|denom| > 1e-14` -> `re^2+im^2 > 1e-28` is
**mathematically equivalent but not BIT-equivalent** — rounding can move which
elements pass, changing the set of modes marked valid. For a guard, "same in
exact arithmetic" is insufficient; only "same set selected, in IEEE double"
counts. Every landed reduction was proven on that standard (200 randomised
trials with `denom` = 0, 1e-20, 1e-13, sign flips, pads; 0 mismatches).

Also fixed: a premature capacity refusal that gated the REPLICATED factor's
buffer on the DISTRIBUTED route (which never allocates it), and a loud
announcement when collective-payload chunking cannot honour its own budget
(the bound is exceeded up to 13x at `q_block=1`; no failure has been attributed
to it).

## Two measurement corrections that outlived their claims

- **GB vs GiB**: the planner prints `bytes/1e9`, the harnesses printed
  `kB/1048576` labelled "GB". Every predicted-vs-measured ratio in the campaign
  understated the measurement by 7.37%. Corrected, the model
  **under-predicts by 1.5-14%** — it does not bracket reality, and a planner
  that reads low is worse than one that reads high. Fixed in 10 harnesses.
- **Harness gates produced more false results than the code under test**: a
  hard-coded FFT grid rejected 100% of a correct 45 Ry run for 95 min; a rank
  gate could **fail open** on a wording change; a liveness check read the wrong
  awk field and four healthy 32-node runs were cancelled as "hung". All fixed.
  The lesson that generalises: **when a harness already parses a log correctly,
  call it rather than writing a second parser.**
