## Ranked Phase A findings

1. **P1 — temporary route identity is a cache key without lifetime ownership.** `src/gw/wavefunction_bundle.py:700` constructs a new identity-keyed `ParentSigmaRoute` each time `sigma_face_kernel_kwargs` runs; `src/gw/ppm_tau_kernel.py:338`, `:582`, `:1002` key persistent kernel caches by `id(parent_route)`. The projection closure retains the row table and symmetry object (`:249`), while G closures retain the plan (`:600`), not necessarily the route itself. Repeated calls can miss reuse, and Python can recycle the identity of a discarded route for another route with equal shape and different tables. This is now a measured cache-seam defect (claim 824, JID 57941637 step `lx-Xg0-120808-433431-9147`, `audit/04_cache_producer_probe/probe.log`): the production route constructor/factory reused a recycled identity after 122 allocations, selecting [10] instead of the requested [20]. FFT/GEMM/symmetry backends were stubbed; this does not claim a production GW energy failure. Fix: remove duplicated route state and key by the persistent immutable plan object plus actual face shape; ensure closures/cache keys retain the owner. A discriminator must call the factory repeatedly on one plan, then on two same-shaped plans with different row/actions, and check reuse versus distinct operator results.

2. **P1 — ζ reuse loses parent storage after the planner reordering.** `src/gw/gw_init.py:3313` initializes both selected plans to `None`; `:3366` nests the entire selection in `if not charge_zeta_reused`; `:3419` is the only fresh-path assignment enabling parents-only storage. Thus a non-restart reuse run loads full-k at `:3464`, even if the candidate plan and consumer checks passed. The later `elif gflat_plan is None` at `:3432` is unreachable in the enclosing non-reuse branch after a successful planner return. This is a route/memory regression, not evidence of incorrect energies. `docs/architecture/zeta_fit_face_psi_cct.md:429` says reuse is allowed; the original lane report's leg 10 describes an earlier implementation. Fix: select storage once independently of whether ζ is being rebuilt, then price exactly that storage; keep fresh-fit chunk planning conditional on reuse. Recheck fresh/reuse/restart independently.

3. **P2 — the fused/AOT callable can suppress a required basis permutation at equal extents.** `src/isdf/core.py:7412` restores packed Z only when its μ extent differs from `meta.n_rmu_padded`. A packed permutation can be nonidentity even when both extents are equal (whole-group packing changes row order without necessarily adding pads). C is restored unconditionally in `_c_q_face_parent` (`:1598`), so the composed callable can pair canonical C with packed Z. The ordinary staged driver is protected by the unconditional restore at `:7669` before it calls `solve_phase`; this is not a demonstrated Si driver failure. Two restore owners created the divergent behavior. Fix under the pending restructure: both operands stay packed and the shape-based branch disappears. Before that restructure the old bridge must execute based on order, not shape. The direct C/Z parity test (`tests/test_isdf_zq_parent_parity.py:239`) explicitly unpacks outputs for comparison and does not enter `_make_fit_one_rchunk_kernel.solve_phase`, so its green result does not cover this case. This is a source-derived fused-callable defect; no new numerical failure is claimed. Require an end-to-end C/Z solve oracle with equal extents and a nontrivial permutation, as well as the interior-pad case.

4. **P2 — parent memory is priced twice, then the planner's route can differ from execution.** `src/gw/gflat_memory_model.py:419` adds four parent faces to persistent storage; `src/gw/gw_init.py:3378` already supplies that route to the planner. `:3402` adds another two packed faces to `gflat_plan.hwm_bytes` for admission, with a stale comment that the planner did not know about them. The full-k fallback still retains a chunk plan made with parent-route transients. Fix: one resolved storage/contraction decision and one inventory, with fallback replanning if capacity changes that decision. After the restructure the parent inventory is two faces, not four; μ² and μ×G terms must take the same packed extent as their arrays. Test the budget threshold, not just an unconstrained Si case.

5. **P2 — the temporary two-order API has spread into physics factories.** `src/gw/centroid_k_unfold.py:276`–`:490` owns pack/restore bridges; `src/gw/wavefunction_bundle.py:275` stores both face pairs, `:648` duplicates plan rows/symmetry and two shapes in a route, and `:709` exposes a projection-order string. `src/gw/ppm_tau_kernel.py:243`, `src/gw/w_isdf.py:543`, and `src/isdf/core.py` then make order decisions inside the physics chain. The two-axis seam must use `symmetry_maps.reorder_isdf_operator_basis` (`services/symmetry_maps/src/symmetry_maps/maps.py:944`); current `pack_square_operator` (`centroid_k_unfold.py:297`) instead performs two generic gathers with an intermediate replicated endpoint spec. ## Design and proposed threaded changes

**What design criteria would Jack most likely object to?** A new wrapper that only forwards calls; duplicate symmetry/Green algebra; a generic padding receipt that quietly changes meaning; hidden host gathers; stale route booleans; claims of bit identity through an ill-conditioned solve; and wrappers documented with session history instead of shapes/invariants. Avoid all seven.

* **One centroid-basis owner at the file seam.** Reuse the small basis object the PSIIRR restructure introduces. It should own canonical centroid indices, the existing grouped layout, and one conversion pair. A two-axis operator dispatches to the symmetry service's existing volume-preserving permutation; a small one-axis face/vector uses a gather. Do not put a GW-specific basis type in `runtime.padding` or rebuild permutation algebra in an I/O writer. Do not add a second basis object if the lane has already supplied one. Expected restructure deletion: roughly 150–250 lines of bridges/comments; audit implementation only if the landed version leaves duplication.
* **Remove `ParentSigmaRoute` as shadow state.** Derive projection/G shapes from the one packed parent face pair; use the existing immutable plan for parent row selection, symmetry and cache identity. A factory needs shape metadata and that plan, not a fresh object copying them. Thread this through static COHSEX, invalid-pole Σ, shared τ kernels and MPA; retain the existing Green builder and band projection owner. Estimated net deletion 60–120 lines after the packed restructure. **I would implement this**, with repeat-factory and same-shape/different-plan discriminators plus the requested CPU/P4 gates.
* **Extract parent preparation from the 1,000+ line orchestration function.** A procedural helper should resolve admissible parent storage, build the plan once, load faces once and return the existing carrier/bundle. Select storage independently of fresh/reuse, then feed its inventory to the existing planner. Retain real distinctions: full-k consumers, charge versus Cartesian-current support, and the measured Green profitability policy; those do not disappear merely because μ order becomes unique. Avoid another admission dataclass/enum. Target removal from `prepare_isdf_and_wavefunctions`: 150–250 lines; whole-tree net deletion about 40–100 from repeated fresh/restart preparation and dead branches. **I would implement a bounded extraction after inspecting the lane's final shape**, and fix findings 2/4 in that same concern only if they remain.
* **Do not generalize every `PaddedAxis` consumer to arbitrary index maps.** Bands and contiguous r chunks still use the suffix contract correctly. The grouped layout already owns the active map, so adding it to every serialized receipt creates a second source of truth and risks processor-dependent files. Packed μ is the whole runtime extent; logical counts remain physical counts for disk schema and reporting. Document the boundary in the existing padding owner page and update the binding decision to reflect the owner's packed-order target. Expected net prose change about 10–30 lines.
* **Consolidate band-chunk compaction.** `src/isdf/core.py:2957` introduces `_band_chunk_compaction` but explicitly leaves the same table construction in the full-k kernels. This is duplicated layout arithmetic, not distinct physics. Reuse that one helper across parent, full-face and legacy/coupled consumers where their actual contracts agree; preserve the short-chunk sentinel and refuse incompatible carriers at the same producer boundary. Estimated net deletion 30–70 lines. This is a secondary bounded cleanup if it survives the lane restructure, with remainder-bearing C/Z cases on every affected path.
* **Keep physics oracles; retire bridge-specific tests with the bridges.** `tests/test_parent_projector_unfold_oracle.py` supplies an independent WFN-based oracle; the synthetic C/Z and Σ tests activate antiunitary, spin and glide phases. Preserve those. Retarget crop tests to file conversion and require an interior pad plus a nontrivial permutation so a prefix slice cannot pass. Add a same-file round trip under another emulated mesh layout if the new seam lacks it; the required real P4 fresh/restart comparison alone does not establish processor-grid independence. No new performance claim without optimized HLO evidence.
