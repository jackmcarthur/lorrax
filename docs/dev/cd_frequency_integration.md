## 0. Deviations first
1. **Si "≤ 0.1 meV vs `cd_ibz8_E0`" is not attainable on main and is replaced by a two-tier target (§6, open Q2).** `cd_ibz8_E0.csv` is a native plane-wave, 754-band (complete 30 Ry basis, `full_spectrum.h5`), head-off, hat-basis h = η/8 object (its own basis error is ≤ 0.08 meV frontier / ≤ 0.66 meV for high groups, CD_MODERN_NOTES "Full Gamma pass"). Main has no `file_io/dense_spectrum.py` and no 754-band WFN.h5 (seed WFN has 48 bands), and the production route lives on the ISDF bank. Band sum (754 vs ≤ 128), basis (PW vs ISDF, ≥ 0.08 meV in Σ_x alone) and the reference's own O(h²) error each exceed 0.1 meV. Fe `fe_cd_states.csv` (same tree 79bcc1788, same 312-centroid bank, exact Lehmann on both axes, controls ≤ 0.03 meV) is the attainable ≤ 0.1 meV target.
2. **`input_reference.md` will be hand-edited, not regenerated.** The page itself (lines 5-19) states `tools/gen_input_reference.py` must not be run against it (it flattens prose rows and refuses on missing keys; registered in `tests/KNOWN_FAILURES.md`). The task text asked for regeneration from the parser.
3. Production v1 uses the **exact ordered Lehmann χ⁰** (fe_cd route), not cd_modern's spectral-density/Toeplitz χ⁰. Reason: the hat basis is O((h/η)²) (0.66 meV at η/8) and would miss the 0.1 meV Fe target unless h ≤ η/32; the Lehmann owner already exists on main (`w_isdf.compute_chi0_direct_fractional`, w_isdf.py:3647). The spectral-density route is the v2 accelerator (§4, Q3), kept behind a sub-key, never silent.
4. Head/wing: v1 admits only `head_correction = off` under CD (both references were built head-off); `full` refuses by name until the CD-node head evaluation (§2.5) is certified.

Planner: `nz_c = floor(budget / (4·nq_loc·n²·16 B))` with budget = 0.5 × (device − resident), printed per stage; Fe ≈ 64, Si ≈ 8. Peak per rank: Fe ≈ 8-9 GB, Si ≈ 11-13 GB (A100-40). Rematerialization policy: no autodiff, so `jax.checkpoint` is not the tool; the remat boundaries are the two recomputations above (ρ_q per step, kernel tables per node) plus the chunk pipeline as one `lax.scan` over knot chunks inside `shard_map` (q axis) with per-stage `donate_argnums` (χ→W→t) so nothing outlives its stage. Host side: only the quadrature/selector tables (built once); `io_callback(ordered=True)` carries the per-chunk heartbeat and the ledger sample (`runtime.xla_memory.pool_high_water`, xla_memory.py:399 + `bytes_in_use`). **Leak-audit protocol:** ledger row per (stage, chunk): bytes_in_use before/after, pool high-water; pass = Δbytes_in_use between equal-shaped chunks exactly 0, high-water reached in chunk 1 (compile transient excluded) and flat over all later chunks and over repeated q/k iterations; `len(jax.live_arrays())` constant; red twin = deliberately retain a per-chunk list and watch the slope go positive. Rows go to the lane report's cost table (peak GB per rank per stage).

## 4. Performance plan
Kernel classes, per (z, q): **(A)** Lehmann χ⁰: Σ_pairs M_t(μ) w_t(z) M_t(ν)* = GEMM [n,T]·diag(w)·[T,n], 8n²T flop; restructure by folding the z-weights into the right factor → one GEMM per (q, chunk) with N = nz_c·n (Fe: 312 × 78k × 20k) — compute-bound, AI ≈ n/2 flop/B (156 Fe, 550 Si) ≫ A100 ridge 12.6. Fe harness: 581 s at ~1.1e13 flop/s aggregate (14 % of 4×19.5 TF) with one GEMM per z; target ≥ 50 % after batching. **(B)** Dyson: batched LU n = 312 (Fe) is latency/occupancy-bound by construction (batched getrf on 1024 tiny matrices); its wall share is < 5 % (42 s of 1013), so it is the class whose roofline position is reported rather than tuned; at n = 1100 (3.5 GFLOP per LU) it is compute-bound. **(C)** contraction GEMM [(k,m)·l, n]·[n, nz_t·n] → t, 8·R·L·n²·nz flop, compute-bound (AI ≈ n/2); Fe harness 321 s incl. (D)/(E), restructure = z-batched N axis + banded real-axis rows (below). **(D)** off-diagonal/diagonal reduction Σ_ν t·ρ* → [k,m,n,l]: 8·R·L·n·nb flop, AI ≈ 0.5-1 flop/B — DRAM-bound; kept ≤ 10 % by sizing nz_t so t is read once. **(E)** kernel laws (elementwise + reduce over l): memory-bound, small. Algorithmic lever (cd_modern item D): on the real axis a (l, E) row touches only the two knots bracketing x = E − ε_l, so the residue contraction is done per knot chunk on the gathered row band (2·L·n_E rows vs L·J): 20× fewer real-axis contractions on a ±5 eV grid, 2× on the −95 eV Fe deck; the imaginary axis keeps N_u = 96 full contractions. χ⁰/Dyson still run at every knot (reach is set by the semicore read). **Measurement protocol:** NVTX via `common.jax_profile.annotation` (jax_profile.py:83) per class; `nsys profile -t cuda,nvtx --capture-range=cudaProfilerApi` on rank 0 of the P=4 leg (one node, `lx run … -N 1 -G 4 -n 4`); `ncu --section SpeedOfLight --section Occupancy --launch-skip S --launch-count 5 -k regex:<class>` on 5 launches per class; **dcgmi trap**: `dcgmi profile --pause` before ncu and `--resume` after (nv-hostengine holds the profiling counters; otherwise ERR_NVGPUCTRPERM/hang). Report per class: `sm__warps_active.avg.pct_of_peak_sustained_active` (achieved occupancy), `sm__throughput`, `dram__throughput`, and the **fraction of GPU-active wall spent in kernels whose class occupancy ≥ 50 %** (nsys durations weighted by class), plus host-gap fraction. Owner target: sustained > 50 % warp utilization over the Σ stage; expected after restructuring: (A),(C) > 50 %; (D),(E) at the DRAM roofline (occupancy reported, throughput-limited); (B) named with its latency roofline. v2 lever if (A) dominates after batching: cd_modern's hat-basis spectral density in the ISDF basis (A[nodes, n, n] blocked over ν columns, analytic hat kernels, Toeplitz/FFT via `common.fft_helpers.local_fftn3` inside `shard_map`) — χ⁰ at all J knots for ~2 GEMM-equivalents, O((h/η)²) with h ≤ η/32 for ≤ 0.05 meV; gated against (A) by a cd_modern-style Certificate A.
